🛰️ Data API

Query the whole Argo array — by sensor serial number, model, WMO, region, or type — straight over HTTP with DuckDB or pandas. Free, no key, no rate limit. Data © Argo, CC BY 4.0.

What makes it useful unique

The GDAC is a file server; argopy, Argovis, and ERDDAP already do excellent space/time/parameter queries of profile data — use those for that. What none of them offer is a serial-number / sensor index: going from a physical CTD or optode (its serial, model, or maker) to the float it's on. That's this API's reason to exist.

Endpoints

Base: https://vladsimontov.github.io/ArgoFloatData/api/

FileWhatRows
sensors.parquet one row per (float, sensor): WMO, sensor, model, maker, serial no.~75k
floats.parquet one row per float: type, platform, position, params, data path~20k
floats.json compact per-float index for JS/browser use (each row has its GDAC data_url)~20k
index.json self-describing manifest: files, schema, counts—

Query it

DuckDB — SQL straight over HTTP (nothing to download)

-- Which float carries CTD serial 17106?
SELECT wmo, sensor, sensor_model, sensor_maker
FROM 'https://vladsimontov.github.io/ArgoFloatData/api/sensors.parquet'
WHERE sensor_serial_no = '17106';

-- Every 6000 m Deep float (SBE61 CTD) — a lookup no other Argo API offers
SELECT DISTINCT wmo, sensor_serial_no
FROM 'https://vladsimontov.github.io/ArgoFloatData/api/sensors.parquet'
WHERE sensor_model = 'SBE61';

-- BGC floats in a lat/lon box, with each float's GDAC data file
SELECT wmo, last_lat, last_lon, expected_rel
FROM 'https://vladsimontov.github.io/ArgoFloatData/api/floats.parquet'
WHERE data_kind = 'bgc'
  AND last_lat BETWEEN 30 AND 45 AND last_lon BETWEEN -10 AND 40;

pandas

import pandas as pd
B = "https://vladsimontov.github.io/ArgoFloatData/api/"
sensors = pd.read_parquet(B + "sensors.parquet")
sensors.query("sensor_model == 'SBE61'")[["wmo", "sensor_serial_no"]]

JavaScript / any HTTP client

const floats = await (await fetch(
  "https://vladsimontov.github.io/ArgoFloatData/api/floats.json")).json();
const deep = floats.filter(f => f.deep);   // each row has f.data_url (GDAC NetCDF)

Getting the actual profile data

Every float row carries a data_url / expected_rel pointing at its NetCDF on the GDAC — fetch that directly, or for gridded space/time queries use argopy / ERDDAP / Argovis. This API doesn't rehost the ~200 GB of profile data; it indexes it.
